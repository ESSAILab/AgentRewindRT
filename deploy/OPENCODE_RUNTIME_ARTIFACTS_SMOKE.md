# OpenCode 临时动态库核验与部署验证

本次优化适用于新生成的记录，历史分析不自动重算。宿主机入口、后端和 Web UI 需要一起更新；无需数据库迁移。

## 处理规则

启动前记录 OpenCode 程序指纹和临时目录已有文件。退出后，只有工作区外、新增且符合命名形式的临时 ELF 动态库，在 nono 元数据确认新增和大小一致、无符号链接、程序启动前后指纹一致、完整文件字节存在于该程序内嵌内容中时，才标记为“已核验运行依赖”。保留原始 diff、路径、大小和指纹，但不单独据此判定用户任务越界。

这是对本机所选程序内嵌内容的身份核验，不证明程序来源可信或精确创建进程。没有忽略整个 /tmp 或所有 .so 文件。未知库、已有文件变更、工作区内文件、核验异常均保留常规审查。未展示内容不能等同于空文件；相关记录至少要求人工审查。

程序核验上限 512 MiB，单库 64 MiB，每轮最多 16 个候选文件；超限不豁免。启动前后读取程序会增加少量 I/O 和内存开销。nono 对新增或修改文件重复输出的完全相同尾部预览不再重复计数，非重复内容及独立差异块保留；原始归档保持完整。

## 更新与复测

更新仓库代码后，按 [多轮部署说明](OPENCODE_INTENT_SMOKE.md#部署范围) 同步宿主机入口、后端和前端。必须包含 `runtime_artifacts.py`、`diff_parser.py` 和采集插件；无需数据库迁移。备份本地修改后再更新代码，不依赖旧会话中临时生成的压缩包。

在已配置宿主机路径、模型及服务环境变量的仓库根目录执行：

```bash
./scripts/agentguard-compose up -d --no-deps --build ai-agent web-ui
./scripts/agentguard-compose ps
```

重新运行 [agent 冒烟](AGENTGUARD_SMOKE.md#执行真实智能体用例) 或多轮交互，查找新 run_id：

- 已核验临时库仍显示路径、大小、SHA256 和核验理由，不单独据此判定越界。
- 未产生临时库时，不应生成虚假依赖记录。核验失败时保留常规审查。
- 新增与修改文件的行数应与实际差异一致，不重复计算尾部预览。
- 业务文件有独立风险时仍可告警，不保证所有运行都为 low/allow。
- 旧记录不自动重算；完整原始 diff 仍保留在归档存储中。

实际通过的场景见 [验证记录](OPENCODE_VALIDATION.md)。
